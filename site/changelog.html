未发布

master · 尚未发包

凭据在屏幕上也会被遮住

  • 密码框的值显示为 ••••••；凭据语境中的 3–8 位数字（验证码、PIN、CVV）显示为等长圆点，前后的词保留，策略仍能分类。
  • observe、动作后的 diff、read-list、screenshot、--trace-shots 与 report 共用同一份脱敏后的屏幕；截图的对应区域盖成灰色。
  • 被遮住的元素无法再按原文找到：tap --text 482913 返回 not_found，Agent 只能请人接手。
  • 策略与脱敏使用同一套凭据词表；低层 agent.captureLayout() / captureScreen() 仍返回设备原样数据。

设备状态也有名字

  • 新增 device_locked、device_needs_setup、device_offline 三个状态，退出码统一为 2：Agent 一看就知道该请人解锁、点「允许 USB 调试」，还是插线，而不是重试同一条命令。
  • 锁屏识别放在屏幕模型里（锁屏 bundle / ScreenLockWidget）：observe 不再把锁屏当成一个可点的页面，动作命令在碰设备之前就以 device_locked 停下。
  • 连接阶段改读 hdc list targets -v：Unauthorized 报 device_needs_setup，Offline 或没有目标报 device_offline；多目标时优先选 Connected 的那台。

同一条审批可以记住

  • --approval-id 兑现时加 --approval-scope task（本任务内这个应用的这条规则不再问）或 always（这个 state dir 的所有任务都不再问）；默认 once，只兑现这一步。
  • 记住的授权按 rule + bundle 匹配，存在 grants-<hash>.json；它只跳过审批这一项检查，凭据、--read-only 与 --apps 白名单仍然生效。
  • resume 清掉 task 范围的授权：人接管后批准它的上下文已经不在，Agent 要继续就得重新问；always 是人的长期决定，保留。
  • 审批状态的提示语直接教 Agent 用这两个 flag；status 列出当前记住的授权。

升级后 Skill 自己跟上

  • 安装 Skill 时在目录里写 .uitest-skill.json：包名、版本与两个文件的摘要。
  • mcp 启动前检查：包已升级、且副本仍是本包写的那份，就地把 SKILL.md / REFERENCE.md 更新到当前版本，不用重跑 install-skill --force。
  • 人改过的副本（摘要不符）与手写的 Skill（没有记录）不动；0.3.0 装的副本按发布时的精确摘要识别后接管，老用户也能自动升级。
  • 刷新失败不会阻止 MCP server 启动；已经是最新版本时启动没有任何额外输出。

更多 Agent 一步接好

  • connect --agent gemini 写 ~/.gemini/settings.json 的 mcpServers；--agent copilot 写 ~/.copilot/mcp-config.json，条目按 Copilot CLI 自己的 schema 带 type: "local" 与 tools: ["*"]。
  • 四家 Agent 共用同一条「只改自己那一项」的写入路径：注释、键顺序、邻居排版不动，已经正确时零写入；Agent 目录不存在时创建，不再因缺少父目录而失败。
  • Gemini 不写 trust：逐次工具确认保持默认，审批仍由本包自己的策略层负责。

0.3.0

2026-11-16 默认值、接管与交接

四处功能修改，都来自「默认值不该替人放行」这一条：Agent 能做的动作更安全，人也能随时把手机拿回来。

删除与发送默认要审批

  • 默认审批集从「支付、金融」扩到「支付、金融、删除、发送」——这四类是 Agent 做了、人收不回来的事。
  • commits（确认 / 保存）仍不默认：手机上半数普通表单按钮都叫这个，每次都问会把人训练成不看就点同意。
  • 与之前的 --read-only 失效同类：默认值放行了人不会希望 Agent 自主执行的动作。

人可以随时接管

  • uitest-phone hold 把设备租约写成 "held by a person" 后退出；Agent 命令随后以 lease_held（退出码 2）停下。
  • 可以抢走正在运行的任务，包括整个进程只持一次租约的 mcp 会话：任务在下一条命令前发现租约没了，不会在动作中途被打断。
  • resume 交还；只释放 hold，别的任务的租约不碰；同一个 Agent 会话下一条命令自动重新取得设备，不用重启。
  • hold 不按进程存活判断，所以不会自己过期，也没有命令能把它抢回去。
  • 实测：hold 之后一条 Agent 命令 2.3 s 退出 2，提示「A person is using the phone. Stop and wait; they will run uitest-phone resume.」；MCP 会话在 hold 期间的工具调用返回 lease_held，resume 后下一条恢复 settled。
  • 设备侧的 UI 事件流不可用于判断「人在动手机」：会关掉会话、能把 daemon 卡死，且合成点击也被当成手指。所以接管是人的明确声明。

Agent 可以请人接手

  • uitest-phone handoff --reason "请登录后继续"（MCP 工具 uitest_handoff）把手机交给人并立即返回 handoff（退出码 2）：Agent 遇到登录、验证码、解锁这类只有人能做的一步时，不再猜或试图绕开。
  • 原因写进租约，之后每个拿到 lease_held 的命令都会重复它；人做完后 resume，同一个 Agent 会话下一条命令自动继续。
  • 与 hold 是同一条租约、同一个 resume：不做两套状态机。真机实测 MCP 会话 handoff → 同一会话 lease_held → resume → settled。

一步接好 Agent

  • uitest-phone connect 把 MCP 注册直接写进 Agent 自己的设置文件，只改自己那一项；注释、键顺序、其它 server 的排版原样保留，已经正确时零写入。
  • 支持 claude（~/.claude.json）与 codex（~/.codex/config.toml）。文件解析失败就拒绝并报出偏移，不替人重写。
  • 入口写成本包绝对路径 + 当前 node：从 Dock / 开始菜单启动的 Agent 看不到终端 PATH。
  • install-skill 同时写 ~/.claude/skills 与 ~/.agents/skills（agentskills.io 跨 runtime 别名），一次覆盖 Claude Code、Codex、Copilot CLI、Gemini CLI。

修复

  • lease_held 的退出码一直是 1：Session.open 在命令执行前抛错，而错误分支统一返回 1。现在按错误类型映射为 2。
  • 被 hold 的设备上，命令要挂 60 s 才被杀死：Session.open 失败时设备连接没关，进程不退出。现在立即释放并退出 2。
  • hold 不生效：租约按 pid 判断存活，而写租约的命令早已退出，下一条 Agent 命令立刻把设备抢回去。新增 hold 标记跳过存活判断。

0.2.0

2026-11-16 命令行与 Agent

SDK 之上多了一层给人和 Agent 用的命令行：每条命令开一次设备、执行一步、等 UI 稳定、打印屏幕或 diff、释放设备。同一套命令既走 CLI，也走 MCP。SDK 的公开接口只增不改，0.1.0 的代码不用改。

命令行

  • 19 条命令：observe、tap、type、swipe、double-click、drag、fling、pinch、key、wait-for、read-list、scroll-until、launch、apps、window、doctor、screenshot、report、status。
  • 实测端到端：status 1.2 s、apps --current 1.5 s、observe 1.7 s、doctor 1.9 s、tap --ref 2.3 s（含 Node 启动与设备打开）。
  • 屏幕模型：每行一个元素，带 ref、角色、标签、中心点与状态；动作后打印 diff。
  • 设备侧稳定：动作后先 Driver.waitForIdle，再由 host 轮询两次相同哈希，超时记为 uncertain 而不是抛错。
  • 退出码即结果：0 settled、1 uncertain/not_found、2 lease held、3 待审批、4 被拒。

跨进程状态

  • ref 表存在 <state-dir>/refs-<hash>.json：observe 打印的 ref 在下一条 tap 里仍指向同一元素；不在当前屏幕就 not_found，绝不悄悄指向别的控件。
  • 审批 id 存在 <state-dir>/approvals-<hash>.json：一次性、10 分钟 TTL、绑定命令与目标签名；页面变了返回 stale。
  • 报告按 task 把各进程写的 trace 读回来，跨文件重新编号，覆盖整轮任务——包括 apps、launch 这类不走屏幕动作的命令。
  • 设备序列号在任何文件与输出里都只以 8 位哈希出现。

安全

  • 策略层按标签分类：凭据类永久拦截，支付与金融默认需要人工审批，--confirm 可把删除/发送/确认也纳入。
  • 审批由 CLI 自己校验，不是靠提示词约束 Agent。
  • 一台设备一个任务：第二个任务在碰设备之前拿到 lease_held。
  • 被强杀的客户端会在 daemon 上留下 CLOSE_WAIT 死连接并永久锁住设备；connect() 只在没有任何活连接时才重启 agent daemon。

Agent 接入

  • npx uitest-sdk mcp：stdio 上以 JSON-RPC 2.0 暴露 uitest_<command>，整个进程只开一次设备。
  • npx uitest-sdk install-skill：把随包发布的 Skill 写进 Agent 的 skills 目录，命令与二进制永远同版本。
  • --trace-shots 每步存截图，报告里的链接相对报告自身，截图与 HTML 可整体搬走。

SDK 新增（兼容）

  • Session、ScreenReader、Components、Gestures、AppManager、Policy、Approvals、Lease、TraceRecorder、DevicePool 全部导出。
  • Device 新增 readonly hdc 与 readonly deviceId；原有成员与方法签名不变。
  • isBusyException 参数放宽为 unknown（设备 1.2.x 会把异常发成对象），新增 exceptionText()。

修复

  • --read-only 之前从未生效：布尔 flag 以 kebab-case 存、以 camelCase 读，被静默丢弃。
  • 报告里的截图链接指向文件系统路径，浏览器打不开；改为相对报告目录的正斜杠路径。
  • 同一毫秒创建的两个 trace 记录器文件名相同，后者会截断前者的文件。
  • apps、launch、doctor 之前完全不进 trace，报告漏掉改变应用的那一步。

工程

  • npm 包 919.4 kB / 84 个文件，新增 dist/bin.js 与随包 Skill；SDK 运行时导出 81 个。
  • 335 个单元测试；--version 与 MCP 握手都从 package.json 读版本，不再有第二处字面量。

0.1.0

2026-11-15 首个公开版本

把鸿蒙 uitest 扩展封装成 Node.js SDK：一条长连接做 UI 自动化，一条 gRPC 通道做投流与录制。发布到 npm，官网与文档同步上线。

传输与生命周期

  • 一条 TCP 长连接（agent.so，8012）承载全部 UI 请求，串行队列 + 指数退避。
  • 自动按 ABI 推送 agent.so 与 libscreen_casting.z.so；缺失时才推送。
  • 多实例安全：复用已监听的 daemon，只杀自己拉起的那个；ownDaemon 显式控制。
  • 断线后下一次调用自动重连，失败中的请求不重放；超时即断连。

UI 自动化

  • 点击、原子触摸、三段式滑动、文本输入、按键、UI 事件流。
  • 实测：点击 8–30 ms（中位 9 ms），滑动 389–395 ms，整屏截图 109–222 ms。
  • 对比 hdc CLI：点击 59.0×、滑动 6.9×、截图 4.5×。

截图与 UI 树

  • captureScreen()：起停采集流取首帧，608×1344 JPEG 直接是字节。
  • cropToWindow()：整屏采集 + 按节点 bounds 裁剪，弥补设备没有窗口级截图。
  • captureLayout() 整屏树快于 dumpLayout + pull；后者保留用于窗口过滤。
  • 对比 snapshot_display：agent MJPEG 178–212 ms vs 675–684 ms，快 3.2–3.8×。

投流与录制

  • H.264 over gRPC（6.8 casting），实测 15–89 fps，支持 15/30/60/120 目标帧率。
  • x86_64 模拟器显式走 MJPEG（10–16 fps），不假装支持 H.264。
  • MP4 录制：设备侧编码器直接写文件，dispose() 关闭 muxer 并拉回；使用 casting -m 1 路径。

工程

  • npm 包 840.8 kB / 38 个文件，含三个签名扩展、docs/api.md 与可运行示例。
  • prepublishOnly 强制 build + 85 个单元测试；npm test 不碰设备。
  • 真机验收 16/16 PASS；官网零外部请求，视频 1920×1080 / 30 s。
  • Node.js ≥ 20，ESM，TypeScript 类型随包发布。
