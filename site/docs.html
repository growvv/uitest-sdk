使用文档

uitest-sdk 0.3.0 · Node.js ≥ 20 · MIT

把鸿蒙 uitest 的设备侧扩展封装成 TypeScript API：一条 TCP 长连接（agent.so）负责点击、滑动、截图与 UI 树；另一条 gRPC 通道（libscreen_casting.z.so）负责 H.264 投流与 MP4 录制。0.2.0 起，同一套能力还有一层命令行，可作为 uitest-phone 使用，也能以 MCP 暴露给 Agent。

1. 安装与前提

npm install uitest-sdk
npx uitest-sdk doctor      # 确认设备与所需能力都在
  • Node.js ≥ 20，ESM（import）。
  • hdc：DevEco Studio 自带的 hdc 在 PATH 上，或设置 HDC_PATH，或传 Device.connect({ hdcPath })。
  • 一台设备：真机或模拟器，hdc list targets 能看到。
  • 扩展文件：已随 npm 包发布在 assets/ 下（arm64/agent.so、arm64/libscreen_casting.z.so、x86_64/agent.so），Device.connect() 会自动推送缺失的那份。
  • H.264 与录制需要 arm64：x86_64 模拟器只有 MJPEG。

扩展必须由华为签名才能在真机加载（XPM 校验拒绝未签名 .so）。本包内置的是实测可用的签名版本。

2. 快速开始

import { Device } from "uitest-sdk";

const dev = await Device.connect(); // 只有一台设备时可省略参数
try {
  const { width, height } = await dev.agent.getDisplaySize();

  await dev.agent.click(width / 2, height / 2);
  await dev.agent.swipe(width / 2, height * 0.7, width / 2, height * 0.3);

  const jpeg = await dev.agent.captureScreen(); // 608×1344 JPEG
  console.log(`captured ${jpeg.length} bytes`);
} finally {
  await dev.dispose();
}

可运行的版本在包里：node_modules/uitest-sdk/examples/quickstart.mjs。

3. 核心概念

坐标

所有触摸坐标都是逻辑显示坐标，即 getDisplaySize() 返回的那套（例如 1216×2688）。captureScreen() 默认按 scale: 0.5 出图（608×1344）；把截图上的点换回显示坐标，乘以 display.width / 608。

扩展与 daemon

Device.connect() 依次完成：读 ABI → 推送对应 agent.so（必要时也推 casting 扩展）→ 如果没有 daemon 在监听 8012 就拉起一个 → 建 hdc fport 隧道 → 连上 TCP → 用一次 getDisplaySize() 做健康检查。任何一步失败都会清掉自己建立的隧道与 daemon，然后抛错。

失败即报错

每个失败都是 UitestError 的子类，带稳定的 code。SDK 不做静默降级：能走 H.264 就走 H.264，走不了会通过 cast.castKind 明确告诉你走的是 MJPEG。

5. AgentClient：UI 自动化

所有方法都返回 Promise，失败抛 UitestError。

显示

await dev.agent.getDisplaySize();     // { width: 1216, height: 2688 }
await dev.agent.getDisplayRotation(); // 0 / 1 / 2 / 3

触摸

await dev.agent.click(x, y);
await dev.agent.touchDown(x, y);
await dev.agent.touchMove(x, y);
await dev.agent.touchUp(x, y);
await dev.agent.swipe(x1, y1, x2, y2, { steps?: number; durationMs?: number });
  • click = touchDown + touchUp，实测 8–30 ms。
  • swipe 默认 steps: 8、durationMs: 300，是 touchDown + N 次 touchMove + touchUp 的三段式；中途失败会先 touchUp 再抛错。
  • 坐标四舍五入为整数。

文本与按键

await dev.agent.inputText(x, y, "hello"); // hypium Driver.inputText
await dev.agent.triggerKey(keyCode);

截图

const jpeg = await dev.agent.captureScreen();               // 608×1344 JPEG Buffer
const jpeg2 = await dev.agent.captureScreen({ scale: 1 });  // 1.1.10 上 scale 无效

实现是「起一次采集流 → 取第一帧 → 停止」，这是设备上最快的整屏路径。

连续取帧（MJPEG）

for await (const jpeg of dev.agent.streamScreen({ scale: 0.5 })) {
  // jpeg 是完整的 JPEG Buffer
  if (done) break;
}

采集是脏区驱动的：静止画面只出 1 帧然后不再出帧，这不是卡死。断开循环会自动 stopStream()。

UI 事件流

for await (const ev of dev.agent.streamUiActions()) {
  console.log(ev.type, ev);
}

只上报真实用户输入；通过 agent 注入的合成触摸不会回传。stopCaptureUiAction 会关闭会话。

事件与低层接口

const off = dev.agent.onFrame((jpeg) => void 0);
const offClose = dev.agent.onClose((err) => void 0);
dev.agent.connected; // boolean
dev.agent.close();   // 主动关闭，之后不再重连

await dev.agent.call("CtrlCmd", { api: "getDisplaySize", args: [] });
await dev.agent.hypium("Driver.screenCapture", "Driver#0", []);

call 的 method 只能是 "Captures" / "CtrlCmd" / "Gestures" / "callHypiumApi"。

6. Session 与命令行

Session 是 SDK 里「一个任务看一台设备」的那一层：它持有租约（两个任务不能交错）、策略（危险步骤在碰设备前停下）、ref 表（ref 只指向它被观察时的那个元素）和 trace。CLI 的每条命令都只是开一个 Session、跑一步、关掉。

直接使用 Session

import { Device, Session } from "uitest-sdk";

const dev = await Device.connect();
const session = await Session.open(dev, { task: "check WLAN" });
try {
  await session.observe();                 // 读屏并记录
  const r = await session.tap({ ref: 12 }); // 按 ref 点击
  console.log(r.status, r.text);           // settled · 一行 diff
} finally {
  await session.release();                 // 释放租约、关 trace、dispose 设备
}
成员说明
Session.open(device, opts)取设备租约；被别的任务占用时抛 LeaseHeldError，此时设备还没被读写
observe() / screen()读屏并记录；screen() 返回上一次读到的屏幕，没有则新读
tap(target, opts){ref} 走坐标点击，{text} 或 On 走设备自己的 Component.click
type(text, opts)默认输入到焦点框；密码框在任何按键前被策略拒绝
swipe / longPress / doubleClick / drag / fling / pinch手势；pinch 走 PointerMatrix，单指通道表达不了两条同时的轨迹
waitFor / readList / scrollUntilVisible设备侧等待、逐屏读列表、逐屏翻到目标
window(filter, opts)报告焦点窗口或某 bundle 的窗口，可 focus / close
pressKey(key)命名按键或数字 key code
steps本会话已记录的步数
release()结束任务

命令行

安装后命令名是 uitest-phone；npx uitest-sdk <command> 等价，无需全局安装。

uitest-phone doctor
uitest-phone observe --task "check WLAN"
uitest-phone tap --ref 12 --task "check WLAN"
uitest-phone read-list --ref 20
uitest-phone report --title "WLAN check"

全局 flag 对所有命令生效：--task、--state-dir、--device、--read-only、--apps、--confirm、--settle-ms、--trace-shots、--approval-id、--json。完整命令与参数见 --help 与随包 Skill 的 REFERENCE.md。

状态与退出码：settled 0、uncertain/not_found 1、lease_held/handoff 2、approval_pending 3、blocked/approval_denied/stale 4。--json 时输出 {status, code, text, data}。

MCP 与 Skill

uitest-phone mcp               # stdio 上以 JSON-RPC 2.0 暴露 uitest_<command>
uitest-phone install-skill     # 写进 ~/.claude/skills 与 ~/.agents/skills

MCP 进程只开一次设备，工具调用不再付每步的设备启动开销。返回非 settled 的工具调用是 isError: true 的工具错误，文本里带状态与原因，而不是传输失败。install-skill 同时写两个目录：~/.claude/skills 给 Claude Code，~/.agents/skills 是 agentskills.io 的跨 runtime 别名，Codex、Copilot CLI、Gemini CLI 都读它。两个目标先全部检查再写，拒绝时不会留下半套；已有的 SKILL.md 默认保留，除非给 --force。

一步接好 Agentmaster · 未发包

uitest-phone connect                     # 默认 claude
uitest-phone connect --agent codex

把「改配置文件 + 装 Skill」合成一步：只改自己那一项，注释、顺序与其它 server 的格式原样保留；已经正确时什么都不写；文件解析失败就拒绝并报出文件名与偏移，不替人重写。

Agent设置文件Skill 目录
claude（默认）~/.claude.json（$CLAUDE_CONFIG_DIR）~/.claude/skills、~/.agents/skills
codex~/.codex/config.toml（$CODEX_HOME）~/.agents/skills

写入的入口是当前 node 加本包的绝对路径：从 Dock 或开始菜单启动的 Agent 看不到终端的 PATH，裸命令可能解析不到、或被别的程序顶替。只有当本包只存在于 npx 缓存（npm 会清掉它）时，才改写成 npx -y uitest-sdk@<version> mcp。MCP server 在会话开始时读取，接好之后要开新会话。

接管：人要用手机

uitest-phone hold       # 设备归人；Agent 命令 2 秒内以 lease_held（退出码 2）停下
uitest-phone handoff --reason "请登录后继续"   # Agent 主动请人接手，停在 handoff
uitest-phone resume     # 交还给 Agent

hold 把租约写成 "held by a person" 后立即退出。它不按进程存活判断，所以不会自己过期，也没有 Agent 命令能把它抢回去；resume 只释放 hold，别的任务自己的租约不碰——只有取走设备的那个任务能干净地结束。

它可以抢走正在运行的任务，包括整个进程只持一次租约的 uitest-phone mcp 会话。任务不会在动作中途被打断，而是在下一条命令前发现租约没了，返回 lease_held；hold 会打印它从哪个任务手里接过了设备。resume 之后同一个 Agent 会话在下一条命令自动重新取得设备，不需要重启。

Agent 也能反向发起：handoff --reason "请登录后继续" 把手机交给人，立即返回 handoff（退出码 2）。原因写在租约里，之后每个拿到 lease_held 的命令都会重复它；人做完后 resume，同一个 Agent 会话下一条命令继续。MCP 里对应工具是 uitest_handoff，参数 reason 必填——没有原因，人打开手机时只能猜 Agent 要什么。

设备侧没有「人在用手机」的可靠信号：UI 事件流会关掉会话、能把 agent daemon 卡死，而且合成点击也会被当成手指，分不出真假。所以接管是人的明确声明，这也正好是 Agent 唯一能遵守的形式。

7. 投流与录制

const cast = await dev.createCast({
  mode: "stream",   // "stream" | "record"
  frameRate: 60,    // 15 | 30 | 60 | 120，默认 30
  scale: 2,         // 1..5 整数缩小因子，默认 1
});
for await (const chunk of cast.stream()) {
  // H.264: { data, pts, flags, isKeyFrame }；MJPEG: { data, pts }
  if (chunk.isKeyFrame) { /* 从这里开始解码 */ }
}
await cast.requestIDRFrame(); // H.264 专用；MJPEG 上是 no-op
await cast.dispose();

CastOptions

字段类型默认说明
modestream / record必填record 只支持 arm64（需要 casting 扩展）
frameRate15|30|60|12030扩展只认这四个值，其它值会被设备侧静默重置
scale1..51整数缩小因子；越界抛 EBADARG
outputPathstring—record 必填，dispose() 时把 MP4 拉到这里
bitRatenumber8_000_000编码码率
iFrameIntervalnumber2000关键帧间隔
screenIdnumber0屏幕编号
socketNamestring内部常量覆盖抽象 socket 名；同机跑多个投流的唯一方式
durationMsnumber—record：录制时长

CastClient

成员说明
castKind"h264" 或 "mjpeg"，显式选择的结果
stream()AsyncIterable，逐块给出 H.264 / JPEG
requestIDRFrame()请求一个关键帧（H.264）；MJPEG 无操作
dispose()结束投流；录制模式下关闭 muxer 并拉回文件

选择规则

  • resolveCastExtension() 非空 → H.264（gRPC over abstract socket，实测 15–89 fps）。
  • 为空（x86_64 模拟器）→ MJPEG（castKind === "mjpeg"，10–16 fps）。
  • x86_64 上请求 mode: "record" 直接抛 ExtensionMissingError，不会返回一个「录不到东西」的客户端。

录制

const cast = await dev.createCast({ mode: "record", frameRate: 30, outputPath: "out.mp4" });
// 让画面动起来：静止画面不会产生新帧
await cast.dispose(); // 关闭 muxer → 等待设备写完 → 拉回 out.mp4

设备侧文件路径写死在扩展里（/data/local/tmp/mytest.mp4），不可改。编码器是起停驱动的：createCast 返回时已经在录，dispose() 后才完成。

8. UI 树与窗口

整屏 UI 树

const tree = await dev.agent.captureLayout(); // { attributes, children }
console.log(tree.attributes.bundleName, tree.children.length);

窗口截图

设备不提供窗口级截图，SDK 的做法是「整屏采集 + 按节点 bounds 裁剪」：

const jpeg = await dev.agent.cropToWindow({ bundleName: "com.huawei.hmos.settings" });
const jpeg2 = await dev.agent.cropToWindow({ windowId: 12, scale: 1 });

找不到窗口抛 ENOWINDOW，节点没有可解析的 bounds 抛 ENOBOUNDS。

窗口级 UI 树

agent.captureLayout() 永远返回整屏；要按窗口过滤，用 cli.dumpLayout（一次 shell + pull）：

const tree = await dev.cli.dumpLayout({ windowId: 12 });
const tree2 = await dev.cli.dumpLayout({ bundleName: "com.huawei.hmos.settings", withFontAttrs: true });

找节点并点击

import { parseBounds } from "uitest-sdk";

const tree = await dev.agent.captureLayout();
const target = find(tree, (n) => n.attributes.text === "设置");
const bounds = target && parseBounds(target.attributes.bounds ?? "");
if (bounds) {
  await dev.agent.click(bounds.x + bounds.width / 2, bounds.y + bounds.height / 2);
}

10. 错误码

所有错误继承 UitestError，带 code 与可选 cause。

类典型 code触发条件
DeviceNotConnectedErrorENODEVICE / ENOHDC / EHDC / EDISPOSED没有设备、找不到 hdc、hdc 命令失败、Device 已 dispose
ExtensionMissingErrorENOEXT / ENOCAST本地没有对应 ABI 的 agent.so；x86_64 上请求录制
DaemonStartErrorENODAEMON / EPORT / ENOSOCKET / ENORECORDdaemon 拉不起来、端口耗尽、投流 socket 没出现、录制文件没出现
AgentProtocolErrorEPROTO / ETIMEDOUT / EBADJSON / ENOWINDOW / ENOBOUNDS / EBADARG设备返回异常、请求超时、输出不是 JSON、找不到窗口/边界、参数非法
AgentBusyErrorEBUSY全局锁被其它进程占着且重试耗尽；或该设备已有采集流（立即失败）
AgentConnectionErrorECONN连接不可用、请求超时后连接被丢弃、关闭后继续调用

11. 并发与生命周期

  • 一条连接一个在途请求：SerialQueue 串行化；断开后 autoRestart 用新 socket 重连，不重放失败中的请求。
  • 全局锁冲突：只有 Disallow concurrent use 会退避重试（0.5 s 起，抖动后翻倍，最多 40 次，20 s 封顶）。
  • 采集冲突：设备同一时刻只允许一条采集流。Capture already running 立刻抛 AgentBusyError，不会等、不会抢占。
  • daemon 归属：只认本次连接前后新增的、且只有一个的 pid；ownDaemon: true 时才会在 dispose() 杀掉它。
  • 超时即断连：请求超时后连接被丢弃，下一次调用走重连。
  • 退出前 dispose()：撤销 fport，否则本地会留下隧道。

const cast = await dev.createCast({ mode: "stream", frameRate: 30 });
try {
  for await (const chunk of cast.stream()) {
    if ("isKeyFrame" in chunk && chunk.isKeyFrame) {
      // H.264 Annex-B：从这里开始送解码器
    }
  }
} finally {
  await cast.dispose();
}

录制 10 秒

const cast = await dev.createCast({ mode: "record", frameRate: 30, outputPath: "demo.mp4" });

多设备并行

const ids = ["<device-a>", "<device-b>"];
const devices = await Promise.all(ids.map((deviceId) => Device.connect({ deviceId })));
try {
  await Promise.all(devices.map((d) => d.agent.click(100, 100)));
} finally {
  await Promise.all(devices.map((d) => d.dispose()));
}
